# RETAB — 00.007.000

The first PS5 execution of Welcome Tour with 00.006.000 loads all eight NSOs,
initializes Vulkan, then triggers `UnallocatedEncoding` on `D65F0FFF` (RETAB)
at PC `0x802f50c0` in rtld. Unmapped-stack errors follow. This does not establish
missing firmware or a corrupted dump.

The core and its wrapper already enable `enable_pauth_returns` from the extended
NPDM. However, `headless/dynarmic/jit_impl.inc` replaces the upstream implementation
and forwarded only the first two translation options. PAuth therefore remained
disabled and address width stayed at 64 bits. GetBlock and EdenPrecompile now
explicitly forward the process option and address width. The batch compilation
model retains the same options. There is no global enablement for legacy processes.

Core PAuth tests are now linked to the JIT actually generated by the port in the
host suite. The port test covers Run with RET/RETAA/RETAB and PACIASP/PACIBSP,
then precompilation and execution on another shared-group member. Disabled
variants must still reject RETAA/RETAB. The native check also verifies options
in the generated sources used by the PS5 binary.

Validation on the build server: before the fix, 6 cases failed (95 failed
assertions). After the fix, 7 cases / 904 assertions pass, including the new Run
and precompilation paths. Targeted engine suite: 387 cases / 1,871,750 assertions
pass. Tests execute synthetic ARM code; no commercial dump is launched on the Mac
or dedicated server. This validation does not prove that the game reaches its menu.

PS5 00.007.000 trial: the previous RETAB block is passed, with no new
ExceptionRaised in the capture. NRO loading and presentation are active. The game
remains black: shader rejection at 5.495 s (texture gather, field 76..80 equal to 2),
then panic 0x4201 at 20.416 s. A causal link between these events is not established.
Presentation FPS does not prove valid game rendering.
